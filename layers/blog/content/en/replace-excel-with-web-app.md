> **In short.** Move from Excel to a web app when several people work on the same data, when monthly reports take hours of manual work, or when errors cost money. An operations app starts at €5,000, takes 6–12 weeks, and launches in stages so work never stops.

## Excel isn't the problem

Excel is the best tool to start with. The trouble begins when the business grows and the spreadsheet becomes the company's operating system: several copies, formulas only one person understands, data typed in twice.

## 7 signs you've outgrown Excel

1. **Several versions of the same file.** "Report_final_v3_correct.xlsx".
2. **Monthly reports take days.** Someone copies data across sheets.
3. **You can't tell who changed what.** There's no row history.
4. **Errors show up late.** At stocktake, at the accountant, at the customer.
5. **Staff see data they shouldn't.** Salaries, margins, purchase prices.
6. **The data doesn't reach phones.** The field team calls to ask about stock.
7. **You pay someone just to keep the file up to date.**

If three or more apply, an app usually pays for itself within the first year.

## What a web app adds

| Problem in Excel | What the app does |
|---|---|
| Multiple copies | One database, everyone sees the same numbers |
| No history | Every change has an author and a timestamp |
| Full access | Roles: sellers see orders, the admin sees margins |
| Manual reports | Reports in one click, in the accountant's format |
| Desktop only | Works on phones, in the browser |
| Input errors | Validation: you can't sell what isn't in stock |

## Example: Bloom florist

[Bloom](/en/work/bloom) kept orders, stock and payments in three separate records. Flower losses only showed up at stocktake. We built an app with an order board by status, batch stock and losses logged by reason. Financial data stayed visible to the admin only.

Before 8 March, load tests showed two simultaneous orders on the last flowers of a batch could both go through. We moved stock reservation into the database as a single operation, and on the busiest sales day there wasn't one out-of-stock order.

## Cost and timeline

An internal operations app starts at €5,000 and takes 6–12 weeks. The cost depends on:

- **the number of modules** (orders, stock, customers, payments, reports)
- **roles** and access rules
- **integrations** (online payments, SMS, accounting)
- **migrating data** from Excel

## How to switch without stopping work

### 1. We watch a working day
Before any screen, we see how the file is really used. Hidden columns and formulas say a lot.

### 2. We start with the module that hurts most
Usually orders or stock. The rest stays in Excel for a few weeks.

### 3. We import existing data
Customers, products and history move over automatically, so nobody retypes anything.

### 4. We launch with a pilot team
One branch or department for 1–2 weeks. We fix, then roll out.

### 5. Excel stays as an export
Any table in the app exports to Excel. The accountant gets the file in the format they know.

## Frequently asked questions

### Can I keep Excel for some things?
Yes. The app exports any list to Excel and can import files on a schedule.

### What happens to the data if we stop working together?
The database and code live in your accounts from day one. You can hand them to any developer.

### Is an app worth it for a 5-person company?
It is when lost time and errors cost more than the app spread over 2–3 years. With 5 people losing 2 hours a week each, that point comes quickly.
